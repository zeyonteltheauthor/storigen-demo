# STORIGEN OS — demo

STORIGEN OS demo: turn any idea into visible thinking through Seven Lenses. Human first. AI assists. The learner decides. By Arrival House Media.

**Live:** https://zeyonteltheauthor.github.io/storigen-demo/

Type an idea, answer the Seven Lenses (Character, Goal, Obstacle, Stakes, Perspective, World, Twist), and watch your thinking become a map, then a story spine built only from your own words.

- Static HTML/CSS/JS: no build step, no login, no API key, works offline.
- Run locally: open `index.html`, or `python3 -m http.server` in this folder.
- Hosted with GitHub Pages (Deploy from branch: `main`, folder `/ (root)`).
- Grade Along lives at `grade-along/`: fictional practice samples, plus a **Grade a paper** mode where Grade Along AI drafts each rubric row and the teacher approves or edits it. Real student papers are not in this repository.

## Grade Along AI drafts

**Private:** the Grade Along page opens on a gate (teacher passcode, or a school invite code plus work email). The app markup sits in a `<template>` and its code runs only after the Worker's `POST /verify` accepts the teacher passcode (kept in sessionStorage for the tab; **Lock** clears it) or a school session (kept on that device until Lock or expiry). Static hosting cannot hide source, but without a passcode or school session nothing renders or works, and the Worker refuses grading. No student papers ship in the page; drafts stay in the teacher's browser. In passcode mode, names and scores stay on the device. For a school account, first names and approved scores are stored for the school's live reports; photos, PDFs and story text are never stored on the server. A privacy policy, terms of service, and a school data agreement are needed before schools outside Arrival House use Grade Along.

In **Grade a paper** (`grade-along/?mode=grade`), the teacher enters the passcode and presses **Grade with AI**. The page resizes up to 3 photos to JPEG (max 1568 px), or turns the ticked pages of a scanned PDF into JPEGs on the device with vendored pdf.js (`grade-along/vendor/pdfjs/`; the PDF itself is never sent), and sends them, and/or the typed story text, with the first name and grade to the `grade-along-api` Cloudflare Worker (`worker/`). The Worker checks the teacher passcode, rate-limits, and asks Claude (`claude-sonnet-5-5`) for structured JSON: a 1–5 level and comment for each of the four Storigen Wonders rubric rows, overall feedback, and a reading note. Each row appears as an **AI draft** that the teacher approves or edits; **Approve review** unlocks only after every row and the overall feedback are reviewed. AI drafts, teacher decides.

- **Several students in one session:** the Students bar adds a student per paper (name, grade, date, facilitator, up to 3 photos or PDF pages each). **Grade with AI** drafts the student on screen; **Grade all with AI** drafts every ungraded student one at a time (spaced to stay under the Worker's 20/minute limit) with progress shown. Click a student to review and approve their rows. The queue is kept in this browser; paper photos are dropped from storage (with a warning) when they are too large to keep.
- **Bulk upload (one file per student):** pick or drop a stack of scanned PDFs or photos on the Students bar (or pick 2+ PDFs in the paper upload and answer yes to *Make each file its own student?*). Each file becomes a student named from the file name (editable); grade, date, and facilitator are copied from the student on screen. In a multi-page PDF, page 1 is treated as the STORIGEN cover sheet and skipped, and the next pages (up to 3) are ticked, with a note to check. A **Grade all with AI** button appears right there. Page thumbnails are drawn only for the student on screen and full-size page pictures only while grading, so about 30 files stay light.
- **Split a class scan:** a PDF with more than 3 pages gets a **Split this scan into students** button (also offered in the bulk panel). The page renders small page pictures on the device and the Worker's `POST /split` says which pages are cover sheets (batches of 20). Each cover starts a student whose pages run to the next cover; the teacher can tap pages to move split points, or use **Split every N pages** (default 2) if detection fails. Each new student gets its cover marked and story pages ticked, and covers are read right away so names replace the file name.
- **Pre/post writing growth:** each session is marked **Pre-writing** or **Post-writing** (with a per-student override), and the label shows on queue chips and score reports. **Save class scores** downloads a small JSON file to the teacher's device with first name, grade, facilitator, date, assessment, the 4 row scores and the total. It holds no story text or images. Approved scores are also kept in this browser's localStorage, on this device only. In a later post session, **Load pre scores** (JSON, or the Download CSV file) matches students by first name plus grade, case-insensitive. A dropdown fixes mismatches, and unmatched students are flagged. A matched post report adds a Pre vs Post table, and **Print class growth** prints a one-page class summary with pre total, post total and change per student, plus the class average per rubric row. Nothing is stored on a server.
- **School site and invite emails (v16):** schools sign in at [gradealong.com](https://gradealong.com) with a work email and invite code (the team passcode stays on the GitHub Pages link). Create school and add teacher email the invite automatically from invites@gradealong.com; replies go to info@arrivalhousemedia.com. The on-screen code is still shown, and Resend invite issues a new code.
- **Class-scan split (v15):** only a printed cover form starts a new student. Lined story pages with Name or Title, and blank pages, are not split points. If the automatic find misses a cover, tap the page; Split every N pages is a manual option only.
- **School permissions (v14):** the school admin can turn on “Teachers can use their own rubrics” (off by default). When it is off, teachers grade only with the school's approved rubrics. The yearly paper cap is set only from the Arrival House owner panel. Drafts and papers in this browser are stored separately for each signed-in teacher (and for the team passcode).
- **School accounts (pilot):** Arrival House can create a school from the owner panel (passcode). The first admin, and later teachers, sign in with a one-time invite code and their work email. Admins add or remove teachers, set the yearly paper cap, and save school rubrics so everyone grades on the same ones. A shared paper pool counts one paper per graded student, warns at 80%, and stops at 100%. The school growth report rolls up pre/post scores by class and by grade. Passcode mode is unchanged.
- **Custom rubrics:** the session's **Rubric** picker defaults to the built-in Storigen Wonders Rubric. **Manage rubrics** opens a builder: a name, a scale per rubric (lowest 0 or 1, highest up to 10), and 1–10 rows. Each row has a title, an optional description, and a description for each level. Optional level names are shared by every row, and the total is computed automatically. Teachers can add, edit, duplicate and delete rubrics. **Import from a document** renders a PDF (first 4 pages) or photos on the device, and the Worker's `POST /rubric` turns them into rubric JSON for the teacher to check in the builder before saving. Rubrics live in this browser's localStorage. **Export** and **Import rubric file** move one `.json` file between teachers, and the rubric id is kept so scores stay comparable. Grading sends the rubric with each paper; with the default, the request and the Storigen behavior are unchanged. Reports, CSV, Save class scores and the growth views handle any number of rows and any scale. Pre and post scores are compared only when both used the same rubric; otherwise the student is flagged **different rubric**.
- **Details from the cover sheet:** when a PDF has a cover sheet, Grade Along can send a picture of page 1 to the Worker as `coverImage`. The Worker reads only the first name, grade, facilitator, and date (no last name, no school) and keeps it out of the grading prompt and the score. Filled fields are marked *from cover · check*; anything the teacher types wins. **Grade all** reads each cover just before grading that student; **Read covers only** fills details without grading.
- **Tests with an answer key (v22):** choose **Test (answer key)** next to Grade a paper. Build a key (question count, A–E choices, optional points, optional short-answer expected/acceptable answers) and save or reuse it; school keys are shared like school rubrics. Scan or upload photos or a PDF (including a class scan split). The Worker's `POST /test/read` (or `/demo/test/read`) only extracts the marked answers; the page scores them against the key. Correct, clear answers and clearly wrong answers are approved automatically. The teacher reviews only flagged items. A test with no flags is finalized automatically. Class item analysis shows percent correct per question. Demo sample: Grade 3 Science Check, with fictional sheets for Maya and Nico.
- **Data retention (v23):** in the Arrival House owner panel (passcode), each school has **Export scores (CSV)** and **Close school**. Closing signs everyone at the school out and sets a deletion date 30 days out; **Reopen school** undoes it. A closed school also offers **Delete school data now** (type the school name to confirm), which removes its teachers, sign-ins, invites, rubrics, answer keys, scores and usage history and keeps only a deletion record (school id and name, dates, row counts) shown under **Deleted schools · written confirmations**. A daily Worker cron (08:00 UTC) deletes data for schools past their deletion date, plus expired sign-ins and expired unused invites. In the browser, **Lock** now signs out and clears that account's grading queue (with paper photos), draft, saved scores and loaded pre scores from this device (it asks first when unfinished papers would be lost); the sign-in screen has **Shared computer? Clear everything on this device**; and **Clear device history** also removes stored paper photos
- **First names only (v24):** whatever a paper or file says ("Testy Mae Brown", "Brown, Testy Mae"), Grade Along keeps only the first name ("Testy") everywhere: the name field (trimmed when you leave it, with a note), cover-sheet reads, class-scan splits, file names, AI feedback (the AI is told to use the first name only, and any middle/last name it copies from the paper is removed in the Worker and again in the browser), printed reports, CSV/JSON downloads, test reads and school saves.
- **Same first name in one class (v24, pairing fixed in v25):** each student in the queue gets a random roster key, and the teacher can type an optional **Last initial** (never read from the paper). Two students with the same first name are flagged in the queue and under the name field; their saved scores never overwrite each other. Pre/post growth (the school report and the on-device comparison) pairs by roster key when both records have one, so two students named Sam each keep their own pre and post. Legacy rows with no roster key still pair by first name + last initial + grade, and stay unpaired when that match is ambiguous.
- **Flag a bad result (v25):** when a school account uses a credit on a writing draft or a test read, the teacher can press **Flag bad result** (wrong student, misread page, garbled text, or other). The credit is restored, once per charge, up to 5 restores per teacher per calendar month (UTC). Over the cap, the flag is still recorded but the credit is not added back.
- **Sample photos and stuck files (v26):** the public demo at `/` and `/demo` now loads Grade 3 Science Check photos from `/grade-along/samples/`, so a 404 page is no longer saved as a JPEG. Switching samples clears and replaces photos. Each photo has a visible remove (×) control, plus **Clear photos**. A photo that cannot be decoded is dropped with a message instead of blocking grading, and saved photos are checked again when the page loads so a stuck file is cleared after this update.
- **Approved scores only (v24):** **Save class scores**, device history and school saves include only teacher-approved students; the save message says how many were skipped. The API rejects unapproved scores.
- **Paper credits (v24):** a test read where nothing is clearly marked (every answer blank or unclear) returns an error and uses no credit. Regrading or retrying the same paper (same first page + first name) within 24 hours is free, even when the school's allowance has run out.
- **Reports:** **Print report** prints a one-page US Letter score report for the student on screen (scores table with full comments and review status, total out of 20, overall feedback); the type shrinks to fit one page. **Print all approved** prints one page per approved student. **Download CSV** gives one row per student.

- In passcode mode, nothing else leaves the device. Drafts can be kept in this browser (localStorage); the passcode is kept for the tab only (sessionStorage). School sessions are kept on that device (localStorage) until Lock or expiry, and approved scores (first name and numbers only) are stored for school reports. The page CSP allows network calls to the Worker only.
- The Worker does not log student content and never stores photos, PDFs or story text. Passcode mode stores nothing. School accounts use a D1 database (`grade-along-db`) for schools, teachers, hashed invites and sessions, shared rubrics, usage and approved scores (first name and numbers only). Secrets live only in Cloudflare (`ANTHROPIC_API_KEY`, `TEACHER_PASSCODE`, `SESSION_SECRET`), never in this repo. Deploy with `cd worker && npx wrangler deploy`; set secrets with `npx wrangler secret put <NAME>` or in the Cloudflare dashboard. Keep existing secret and rate-limit bindings on deploy (`keep_bindings`).


## Works offline

After one visit over http(s), the app runs with no network. `sw.js` precaches the page, styles, scripts, fonts, manifest, and icons using relative paths (so it works at `/storigen-demo/`), then serves static assets cache-first and pages (navigations and `.html`) network-first, falling back to the cache offline, so an open tab always gets the newest page. It deletes older caches on activate. When a new version takes control of an open tab, the page reloads once (guarded against loops). Bump `CACHE` in `sw.js` and the **Grade Along vN** label in the teacher footer on each release.  This release is **storigen-os-v26** / Grade Along v26. Grade Along v22 adds **Test (answer key)** mode for multiple-choice and short-answer tests. The teacher builds or reuses an answer key, scans or uploads the tests, and Grade Along AI reads the marked answers. Scoring against the key happens in the page, not in the model. Clear correct or clearly wrong answers are approved automatically; only blanks, multiple marks, unclear marks, low-confidence reads, and unmatched short answers are flagged for the teacher. A test with no flags is finalized automatically. School keys are shared the same way as school rubrics, and each scanned test counts toward the paper pool. The public demo includes a fictional Grade 3 Science Check key and sample sheets (Maya and Nico). A public demo is at https://gradealong.com/demo and at the GitHub Pages URL with `?demo`. It uses sample papers and rubrics (fictional names only), allows an optional upload, and grades papers through `/demo/grade` or reads tests through `/demo/test/read`, with a shared limit of about 3 papers or tests per visitor per day. Nothing from the demo is stored on the server. The STORIGEN Learning site button should link to the demo, not to school sign-in. `manifest.webmanifest` makes it installable: name STORIGEN OS, short name STORIGEN, standalone display, ink `#1F2937` and parchment `#F7F4EC`. Icons are a lantern-gold `#D1A954` S on ink.

A service worker only registers on http(s), including this folder on a local static server or on GitHub Pages. Opening `index.html` as a file still runs the app; it just cannot install the worker.

## Tests

The Playwright suite lives in `test/`. Serve the repo root, then point the suite at it with `BASE`:

```bash
cd test && npm ci && npx playwright install chromium
cd ..
python3 -m http.server 4173
BASE=http://127.0.0.1:4173/ node test/run.js
node test/pages-smoke.js http://127.0.0.1:4173/
```

`run.js` walks the lens flows and includes an offline check: load the page, `context.setOffline(true)`, reload, and finish a lens flow. `pages-smoke.js` loads the served site and walks one full example through the story reveal. `.github/workflows/tests.yml` installs Playwright and Chromium, serves this repo, and runs both on every push.


On gradealong.com, `/` and `/demo` are served as the app with HTTP 200 (no redirect to `/grade-along/`). That avoids a Chrome ERR_FAILED when the service worker at `/sw.js` (scope `/`) handles the first visit to the domain. The service worker never caches or returns redirected responses.


Teachers can set **Feedback language** (English by default, also Spanish, or same as the paper). AI comments follow that setting even when the paper is in another language. If the languages differ, the draft includes a short “What the story is about” summary and an optional student-facing copy in the paper’s language. On gradealong.com, **Back to demo** goes to `/demo` and the STORIGEN OS mark stays on this site.


Teachers can switch the interface between **English** and **Español** with the EN | ES control in the header. The choice is remembered in this browser. Feedback language stays a separate setting; if the interface is switched to Español and a feedback language has not been chosen yet, feedback defaults to Spanish. Built-in rubric names are shown in the interface language. Grade Along and STORIGEN stay untranslated.
